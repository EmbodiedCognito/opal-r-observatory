# Contributing

Thank you for helping make statistical computing more open and understandable.

## Before opening a pull request

1. Open or find an issue describing the problem.
2. Keep changes focused and document user-visible behaviour.
3. Add tests for domain and security invariants.
4. Run `npm run check`.
5. Explain any new data flow, external service, package execution, or agent capability.

## Product language

Avoid language implying that Opal guarantees a correct model or interpretation. Prefer “proposes,” “suggests,” and “supports review.” Assumptions, uncertainty, transformations, exclusions, and generated code should remain visible.

## Commit style

Use concise imperative subjects, such as `Add proposal validation`.
